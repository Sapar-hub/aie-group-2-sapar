## 1. Паспорт проекта

- **Название:** Детекция штампов ГОСТ на строительных чертежах (гибридный подход YOLO + CV)
- **Автор:** Сапармурадов Сапармурат

Проект реализует детекцию штампов ГОСТ на строительных чертежах с использованием 4 подходов: CV-базовая линия, YOLOv8, Faster R-CNN и гибрид (CNN + CV-уточнение). После сравнения моделей лучшая разворачивается как FastAPI сервис с `/predict` endpoint.

---

## 2. Постановка задачи и контекст

**Предметная область:** Автоматизация анализа строительной документации. Штампы ГОСТ содержат ключевую информацию (номер проекта, дата, масштаб). При оцифровке чертежей их нужно автоматически локализовать для последующего OCR.

**Задача в терминах ML:** Детекция одного класса объектов (stamp) на изображениях чертежей формата A1-A4. Вход — RGB-изображение чертежа, выход — bounding box штампа.

**Целевые метрики:**
- **IoU** (Intersection over Union) — основная метрика точности локализации
- **Precision / Recall / F1** — качество детекции при пороге IoU ≥ 0.5
- **Detection rate** — доля изображений, на которых модель находит штамп
- Время инференса — практическое ограничение для сервиса

## 3. Данные

**Источники:**
- 49 реальных изображений строительных чертежей из открытых источников (https://2d-3d.ru) с ручной разметкой штампов в формате YOLO
- 500 синтетических изображений (250 GOST + 250 copy-paste), сгенерированных автоматически

**Структура:**
```
data/
├── images/
│   ├── test/        # 49 реальных (31 PNG + 18 JPG)
│   └── train/       # 500 synthetic (PNG)
├── labels/
│   ├── test/        # 49 YOLO-разметок (.txt)
│   └── train/       # 500 синтетических разметок
└── gost_stamp.yaml  # YOLO dataset config
```

**EDA (exp01_eda_baseline.ipynb):**
- Размеры штампов: ширина 345-5652 px, высота 102-1254 px
- Aspect ratio: ~3.55:1 (среднее), std 0.41
- PPI: от 200 до 400 DPI (определено через метаданные + ISO 216)
- 49 изображений, 1 класс (stamp)

**Синтетические данные (exp02_synthetic_data.ipynb):**
- GOST-метод: рисует штамп по ГОСТ 185×55 мм с сеткой, текстовыми полями
- Copy-paste: вырезает реальные штампы и накладывает на случайные участки чертежей с трансформациями

## 4. Модели и подходы

### 4.1. CV Baseline (contour-based)
Классический компьютерный подход без обучения:
1. Adaptive thresholding + CLAHE
2. Поиск контуров с иерархией (parent + children)
3. Union box из дочерних контуров
4. Фильтрация по aspect ratio (3.55 ± 25%)

**Результат:** detection rate ~49%, IoU mean ~0.33

### 4.2. YOLOv8n (одностадийный CNN)
- Модель: yolov8n (pretrained on COCO)
- Данные: 500 synthetic train + 49 real val
- Параметры: 50 epochs, imgsz=640, batch=32, GPU T4
- Аугментации: стандартные из ultralytics (mosaic, flip, rotation)

### 4.3. Faster R-CNN (двухстадийный CNN)
- Модель: ResNet50 FPN backbone
- Данные: те же 500 synthetic train + 49 real val
- Параметры: 30 epochs, batch=8, lr=0.001, SGD, step LR
- Fine-tune последних слоёв

### 4.4. Hybrid (CNN + CV Refine)
- Лучшая CNN → CV-уточнение:
  - Aspect ratio проверка
  - Edge density оценка
  - Выбор лучшего кандидата по композитному скору

## 6. Архитектура решения и сервис

```
[Upload Image] → FastAPI (/predict) → CNN (YOLO) → CV Refine → [bbox + confidence]
```

**API:**
- `GET /health` — статус сервиса, загруженная модель
- `POST /predict` — загрузка изображения, возврат bbox

**Стек:** Python 3.10+, FastAPI, Uvicorn, OpenCV, PyTorch, Ultralytics

## 8. Ограничения и дальнейшая работа

**Ограничения:**
- Мало данных (49 real + 500 synthetic) — модель может не обобщать на новые форматы чертежей
- Только CPU inference в продакшене (без GPU)
- Только один класс (stamp)
- Faster R-CNN медленный на CPU

**Что можно улучшить:**
- Больше реальных данных (разметка + краудсорсинг)
- DETR (трансформерный детектор) при наличии GPU
- Сегментация штампов (не только bbox, но и маска)
- OCR текста внутри штампа
