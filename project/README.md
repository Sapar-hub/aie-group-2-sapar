> Проект реализует систему детекции штампов ГОСТ на строительных чертежах. Сравниваются 4 подхода:
> 1. CV-базовая линия (OpenCV: контуры, template matching)

## 2. Предметная область и постановка задачи

### 2.1. Домен и пользователь

**Область:** Автоматизация анализа строительной документации. Штампы ГОСТ — обязательный элемент каждого чертежа (содержат номер проекта, дату, масштаб, лист). Инженеры и архитекторы тратят время на ручной поиск штампа перед OCR-распознаванием.

**Пользователь:** Инженер/архитектор, оцифровывающий пачку чертежей. Сервис автоматически находит штамп, чтобы передать его в OCR — это избавляет от ручного выделения области на каждом листе.

### 2.2. Задача в терминах ML

- **Тип:** Детекция одного класса (`stamp`) на изображениях чертежей.
- **Вход:** RGB-изображение чертежа формата A1–A4 (200–400 DPI).
- **Выход:** Bounding box штампа + confidence.
- **Стандарт:** Штамп ГОСТ — 185×55 мм, aspect ratio ≈ 3.55:1, всегда в правом нижнем углу. На чертеже — плотная сетка с текстовыми полями (структурный prior для CV).

### 2.3. Доменные особенности

- **PPI (Pixels Per Inch):** Чертежи сканируются при разном DPI. PPI влияет на физический размер штампа в пикселях. Определяется через метаданные (PIL) или ISO 216 (подбор стандартного формата бумаги по размерам изображения).
- **Структура штампа:** Составной объект — рамка + сетка ячеек + текст. В CV-подходе это даёт сигнал: контуры с parent+children иерархией хорошо описывают штамп.
- **Вариативность:** Чертежи могут быть повёрнуты, обрезаны, сжаты; DPI метаданных может врать — нужна верификация через ISO 216.

### 2.4. Целевые метрики (почему именно они)

| Метрика | Зачем |
|---------|-------|
| **IoU** | Точность локализации — насколько bbox совпадает с настоящим штампом. Основная метрика. |
| **Detection rate** | Пропустить штамп целиком — худшая ошибка для пользователя. |
| **Precision / Recall / F1** | Качество детекции при пороге IoU ≥ 0.5. |
| **Время инференса** | Сервис должен работать в реальном времени (или близко к нему) — ограничение для продакшена. |

Выбор финальной модели — по балансу F1, detection rate и скорости (практический компромисс).

## 5. Как запустить проект

### 5.1. Генерация синтетических данных

```bash
python -m scripts.generate_synthetic
```

### 5.2. Обучение моделей (Google Colab)

Все эксперименты запускаются в Google Colab (T4 GPU, Free). 

Последовательность:
1. Открыть `notebooks/exp04_yolo_experiments.ipynb` в Colab
2. Запустить все ячейки → YOLO обучение (~3-5 мин)
3. Открыть `notebooks/exp05_faster_rcnn.ipynb` в Colab
4. Запустить все ячейки → Faster R-CNN (~15-30 мин)
5. `notebooks/exp06_hybrid.ipynb` → Hybrid (~2 мин)
6. `notebooks/exp07_comparison.ipynb` → Финальное сравнение

Результаты автосохраняются в `artifacts/metrics/` и пушатся в git.

### 5.3. Запуск сервиса (локально после обучения)

```bash
python -m src.api.main
```

Сервис поднимается на `http://localhost:8000`, Swagger UI на `/docs`.

**Эндпоинты:**
- `GET /health` – проверка работоспособности
- `POST /predict` – загрузка изображения, возвращает bbox штампа и уверенность

Пример:
```bash
curl -X POST -F "file=@чертеж.png" http://localhost:8000/predict
```
