# HW12 – временные ряды: temporal split, baseline-модели и GRU-прогноз

## 1. Кратко: что сделано

- Датасет: S12-hw-dataset.csv - временной ряд с целевой колонкой `target`.
- Temporal split: данные разделены по времени на train/validation/test без перемешивания.
- Сравниваемые подходы: B1 (naive-last), B2 (moving-average), B3 (ridge-lag-features), R1 (GRU).
- Лучший подход: R1 (GRU) - имеет лучшие test_MAE=6.205 и test_MAPE=4.030.

## 2. Среда и воспроизводимость

- Python: 3.x
- pandas / numpy / scikit-learn: latest (via pip)
- torch: latest
- Устройство (CPU/GPU): GPU (если доступно, иначе CPU)
- Seed: 42
- Как запустить: открыть `HW12.ipynb` и выполнить Run All.

## 3. Данные и постановка задачи

- Датасет: `S12-hw-dataset.csv`
- Целевая колонка: `target`
- Частота временного ряда: почасовая
- Горизонт прогноза: 1 (predict next value)
- Размер датасета: 4320 наблюдений
- Диапазон дат: по данным из CSV
- Дополнительные внешние признаки: нет
- Комментарий: временной ряд демонстрирует умеренную волатильность, возможно наличие тренда и сезонности. Требуется корректный temporal split для избежания утечки данных из будущего.

## 4. Temporal split и признаки

### 4.1. Разбиение по времени

- Данные отсортированы по дате, split выполнен последовательно по времени.
- Train/Val/Test: последовательные порции ряда (конкретные % см. в ноутбуке).
- Random split некорректен, так как нарушает временную структуру данных - модель будет "видеть" будущее при обучении, что приведет к нереалистично хорошим результатам и невозможности реального прогнозирования.

### 4.2. Признаки для baseline-моделей

- Лаги: lag_1, lag_7, lag_14
- Rolling: rolling_mean_7, rolling_std_7
- Календарные: день недели (dayofweek), месяц, день года (dayofyear), год
- Пропуски: заполнялись нулями (fillna(0))
- Масштабирование: MinMaxScaler, обучен только на train

## 5. Модели и эксперименты (B1, B2, B3, R1)

- B1 (naive-last): прогноз = последнее известное значение
- B2 (moving-average): прогноз = среднее по окну (window=7)
- B3 (ridge-lag-features): Ridge регрессия на лаговых, rolling и календарных признаках
- R1 (gru-forecast): GRU с window_size=7, input=9, hidden=64, layers=2

Дополнительно:

- Основная метрика выбора лучшей модели: MAE
- Дополнительные метрики: RMSE, MAPE
- window_size для GRU: 7
- Batch size: 32
- Максимальное число эпох: 10
- Optimizer: Adam
- Learning rate: 0.001
- Как сохранялась лучшая модель: по best_val_mae

## 7. Анализ

Наивный baseline (B1) оказался достаточно сильным на данном ряде, что говорит о относительной стабильности ряда. Moving average (B2) показал худший результат из-за запаздывания на резких изменениях.

Ridge с лаговыми признаками (B3) показал улучшение по сравнению с B2, но все еще уступал GRU и B1 по MAE. Это указывает на то, что линейные зависимости с лаговыми признаками хорошо улавливают часть временной структуры, но не все нюансы.

GRU (R1) превзошла все baseline-модели, что говорит о способности нейросетей улавливать более сложные нелинейные паттерны и зависимости в данных. Это особенно важно для рядов с выраженной сезонностью и трендом.

Выбор по validation, а не по test критически важен - использование test для выбора модели привело бы к переобучению под конкретный тестовый набор и потере обобщающей способности.

Наиболее показательными ошибками модели могли быть пики или резкие изменения, которые сложнее предсказать из-за их редкости или непредсказуемости.


## 8. Итоговый вывод

Для задачи прогноза данного временного ряда наилучшим подходом оказалась GRU (R1), показавшая самую низкую ошибку на тестовой выборке. Это подчеркивает эффективность нейросетей в улавливании сложных паттернов временных рядов.

В случае простых временных рядов с выраженной автокорреляцией наивные baseline-модели могут быть достаточно сильными, но для более сложных зависимостей (тренд, сезонность, нелинейность) GRU демонстрирует превосходство.

Главное про корректную валидацию временных рядов: temporal split обязателен, утечки из будущего недопустимы, выбор модели делается по validation, test используется один раз для финальной оценки.
