# HW12 – временные ряды: temporal split, baseline-модели и GRU-прогноз

## 1. Кратко: что сделано

- Датасет: `S12-hw-dataset.csv` - временной ряд с целевой колонкой `target` (почасовые данные).
- Temporal split: 70% train / 15% validation / 15% test (по хронологии).
- Сравниваемые подходы: B1 (naive-last), B2 (moving-average), B3 (ridge-lag-features), R1 (GRU).
- Лучший подход: R1 (GRU) - имеет лучшие val_MAE=4.57 и test_MAE=4.97.

## 2. Среда и воспроизводимость

- Python: 3.10+
- pandas / numpy / scikit-learn: latest (via pip)
- torch: 2.5.1+cu124
- Устройство (CPU/GPU): CUDA (GPU)
- Seed: 42
- Как запустить: открыть `HW12.ipynb` и выполнить Run All.

## 3. Данные и постановка задачи

- Датасет: `S12-hw-dataset.csv`
- Целевая колонка: `target`
- Частота временного ряда: почасовая ( hourly)
- Горизонт прогноза: 1 (предсказание следующего значения)
- Размер датасета: 4320 наблюдений
- Диапазон дат: 2025-01-01 00:00:00 to 2025-06-29 23:00:00
- Есть ли дополнительные внешние признаки: нет
- Комментарий: временной ряд демонстрирует восходящий тренд с видимой дневной/недельной сезонностью. Данные достаточно волатильны с умеренными колебаниями. Нет пропусков. Прогноз осложняется трендом и возможной нестационарностью.

## 4. Temporal split и признаки

### 4.1. Разбиение по времени

- Как именно выполнен `train / validation / test`: последовательное разбиение по времени (хронологическое).
- Какие доли или интервалы использовались: 70% train (3024), 15% val (648), 15% test (648).
- Почему `random split` здесь некорректен: random split нарушает временную структуру данных - модель будет "видеть" будущее при обучении, что приведет к нереалистично хорошим результатам и невозможности реального прогнозирования.

### 4.2. Признаки для baseline-моделей

- Какие лаги использовались: lag_1, lag_7, lag_14
- Какие rolling-признаки использовались: rolling_mean_7, rolling_std_7
- Какие календарные признаки использовались: day_of_week, day_of_year, month, hour
- Как обрабатывались пропуски после построения лагов/rolling: заполнялись нулями (fillna(0))
- Использовалось ли масштабирование и где именно оно обучалось: StandardScaler, обучен только на train

## 5. Модели и эксперименты (B1, B2, B3, R1)

Опишите коротко и сопоставимо:

- B1 (`naive-last`): прогноз = последнее известное значение
- B2 (`moving-average`): прогноз = скользящее среднее по окну 7
- B3 (`ridge-lag-features`): Ridge регрессия на лаговых, rolling и календарных признаках
- R1 (`gru-forecast`): GRU с window_size=24, input=9, hidden=64, layers=2

Дополнительно:

- Основная метрика выбора лучшей модели: MAE
- Дополнительные метрики: RMSE, MAPE
- `window_size` для `GRU`: 24
- Batch size: 32
- Максимальное число эпох: 15
- Optimizer: Adam
- Learning rate: 0.001
- Как сохранялась лучшая модель: по best_val_mae

## 7. Анализ

GRU показала лучшие результаты благодаря способности улавливать нелинейные зависимости в данных. Наивный baseline (B1) оказался достаточно конкурентоспособным (val_MAE=6.44), что говорит о относительной стабильности ряда - следующее значение часто близко к предыдущему. Moving average (B2) показал худший результат (val_MAE=12.65) из-за запаздывания на резких изменениях тренда.

Ridge с лаговыми признаками (B3) значительно улучшил результат по сравнению с B1/B2 (val_MAE=6.02), что указывает на способность линейной модели улавливать часть временной структуры через лаговые признаки. Однако GRU (R1) превзошла Ridge еще на 24% по MAE (4.57 vs 6.02), демонстрируя преимущество рекуррентных архитектур для сложных паттернов.

Выбор лучшей модели по validation критически важен - использование test для выбора модели привело бы к переобучению под конкретный тестовый набор. Наблюдаемое небольшое ухудшение на test (4.57 -> 4.97) - это естественное поведение для временных рядов, где test представляет более поздний период с потенциально другим режимом данных.

Возможные утечки данных в таких задачах: использование будущих значений в признаках (в моей реализации исключено через .shift(1)), неправильное масштабирование ( StandardScaler обучен только на train), использование данных из test в обучение.

## 8. Итоговый вывод

Для задач прогнозирования временных рядов с выраженным трендом и сезонностью GRU является предпочтительным выбором благодаря способности моделировать сложные нелинейные зависимости. Простой baseline на признаках (Ridge) может быть достаточен для относительно стабильных рядов, однако нейросетевой подход обеспечивает существенное улучшение качества.

Главное, что понято про корректную валидацию временных рядов: temporal split обязателен для избежания утечки информации из будущего, выбор модели делается по validation, а test используется только для финальной оценки лучшего подхода.
